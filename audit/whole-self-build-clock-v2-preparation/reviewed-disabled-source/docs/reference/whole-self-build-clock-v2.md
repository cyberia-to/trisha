# Complete compiler proof replay with separate native Linux phases

This opt-in profile preserves the exact frozen full compiler inputs and the logical proof contract of `whole-self-build-ci.md`. It requires a separately reviewed Joy source revision permitting an explicit 14,400,000 ms compacting host deadline. The historical 7,200-second attempt remains a separate immutable result.

## Execution profile

Both C1→C2 and C2→C3 run on free native `ubuntu-24.04` runners with Rust 1.89.0. A committed v2 source selector identifies all twelve native dependency repositories. The frozen input archive, every one of its 111 files, both exact ART1/JOB1 inputs and expected output bytes remain unchanged. Its historical profile is admitted unchanged; the v2 physical clock selection is separate.

The producer uses an internal deadline of 14,400,000 ms and a 14,700-second outer deadline. The fresh verifier uses 7,200,000 ms and 7,500 seconds respectively. Logical and memory limits remain: 20 billion reductions, 1 billion cumulative allocations, 3,145,728 resident nouns, 65,536 frames, 10 billion collection work, 16 MiB artifact bytes and 16,777,216 validation visits. Certificate limits remain 24 GiB encoded, 96 GiB decoded, 12 billion records, 16 billion expanded steps and 262,144 cache slots. Each runtime process retains the 6 GiB sampled RSS ceiling, 30 GiB owned attempt-storage ceiling, 48 GiB free-start preflight before production and pending-certificate download, and an 8 GiB pre-verification/free-space floor. Download additionally reserves the complete proof plus one chunk. The v2 30 GiB sampled storage scope counts both work and results, including source/build caches; this is stricter accounting than the original phase-directory-only guard. No runtime tuning or alternate evaluator/prover is selected.

Every job has a 360-minute hosted ceiling. Producer setup/build, production, pending transfer and metadata each have independent workflow deadlines of 45, 250, 45 and 10 minutes. The final ten minutes are split into a five-minute small handoff upload and an always-run five-minute evidence upload. Fresh-verifier setup/build, pending download, verification, completion transport and metadata are bounded at 45, 60, 130, 30 and 10 minutes, plus a five-minute same-run pointer download. A phase failure prevents all dependent success publication and preserves available raw receipts. Only a reviewed branch push touching the dedicated v2 activation selector or v2 workflow can activate this profile; audit-only commits cannot start it. Manual dispatch uses this same explicit profile. The profile remains disabled until the reviewed Joy pin and activation state are committed.

## Native source and workload admission

Every job fetches fresh committed source revisions from fixed origins, resolves absolute native Rust tools through rustup, uses an isolated Cargo home and target directory, and retains complete source inventories and Cargo closure. Build and runtime children receive sanitized environments; proof and verification children receive empty PATH and no token. Before and after every native phase, binary and compiler/JOB identities are checked. Successful phase completion requires identical full source and frozen-package inventories, exact bootstrap identities and no warnings.

The producer reconstructs JOB1 with `pack-job` and requires byte equality with the frozen job. Complete successful production must match the accepted input/program/output particles, charged reductions, logical depth, expanded steps and complete compiler response. No terminal receipt is inferred from a partial file or resource sample.

## Pending transport

A successful producer has status `produced-pending-fresh-verification`. Its complete certificate may be staged on existing unpublished draft release `389977897` in `cyberia-to/trisha`, under absent tag `candidate-20260916.1`. This staging status is not a fresh-verification or release claim.

The pending manifest uses schema `trident/whole-proof-pending/v2` and status `pending-fresh-verification`. It binds the repository, Actions run ID/attempt, workflow revision, generation, complete clock profile, source selector, frozen input asset, exact compiler/JOB identities, producer binary/tool identities and producer report. It records the complete certificate size/SHA-256 and ordered contiguous chunk offsets, sizes, SHA-256 values and immutable release asset IDs. Chunks are at most 1 GiB. A final whole-file reconstruction digest from independently downloaded chunks must match the original before the pending manifest is published.

Every asset publication checks the fixed release ID, draft state, tag name, absent tag and unpublished state directly before and after upload. Listings are paginated. Each returned asset must have uploaded state, exact fixed-repository API origin, expected unique name/size/digest and unique membership in the fixed draft. No asset is overwritten, renamed or deleted. Chunk buffers are released before their independent readback; at most one extra chunk is present. The small same-run Actions handoff contains only the pending manifest and its exact server pointer/identity. A complete manifest is never emitted for interrupted staging.

## Independent verification and completion

The dependent verifier job admits only a handoff from its own workflow run, attempt, exact revision and generation. It checks the source selector, profile and immutable input identities against its committed configuration before downloading. It independently fetches the pending manifest by fixed-repository asset ID and requires exact byte equality with the handoff. Every referenced part must be unique, ordered, contiguous, nonempty, within the certificate and chunk caps, and belong to the fixed draft with matching server metadata. Download writes have explicit byte/time/free-space limits. Ordered reconstruction must match the full expected certificate size/SHA-256 before any verifier is executed.

The verifier is independently built from the same committed native source pins. A fresh process with empty PATH checks the downloaded certificate against the exact expected compiler and JOB. Its receipt must match accepted semantic coordinates and the producer's complete certificate counters; it cannot contain prover-only observations. The extracted ART1 must match the exact accepted C2/C3 bytes. Source, input, executable, bootstrap and complete certificate identities are rechecked before completion.

Only a successful fresh verification permits schema `trident/whole-proof-completion/v2`, status `fresh-verified`, on the same unpublished draft. It binds the complete immutable pending manifest by asset ID and SHA-256, the exact certificate, source/profile/input selectors, verifier executable and toolchain, verification report, output identity and a hash-pinned raw evidence archive. The original pending manifest remains immutable. Missing completion or any failed phase means pending/incomplete evidence, regardless of successful chunk integrity. No promotion, tag or default-branch change occurs.
